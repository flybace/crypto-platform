# 自动交易风险与限额策略

## 文档信息

| 项目 | 内容 |
|---|---|
| 适用项目 | D:\code\crypto-platform |
| 目标模式 | 自动现货卖出并换取 USDT |
| 首选运行模式 | `SELL_ONLY` |
| 状态 | 设计基线，未授权真实交易 |
| 版本 | 0.1.0 |

本文件定义自动交易服务端必须执行的安全政策。它不是 Binance API Key 权限说明，也不是投资收益承诺。所有金额、比例和交易范围必须由用户在真实账户启用前明确配置。

## 1. 自动化定义

系统完成一次性授权和限额配置后，可以在授权有效期内自动提交符合策略的订单，不要求用户逐笔确认。以下事件仍需要用户重新授权：

- 首次启用真实交易；
- 增加交易所或交易对；
- 提高任何额度；
- 启用买入、保证金、合约或市价单；
- 启用全部退出；
- 解除硬风险暂停；
- 扩大 API Key 权限。

系统默认关闭真实自动交易。没有有效授权、白名单和非零限额时，订单提交路径必须不可达。

## 2. 运行模式

### 2.1 `DISABLED`

默认模式。允许行情、回测、模拟、只读账户和对账，不允许真实订单。

### 2.2 `SELL_ONLY`

第一阶段唯一的真实交易候选模式：

- 仅中心化交易所现货；
- 仅 `SELL`；
- 仅出售账户已有的可用基础资产；
- 默认结算到 USDT；
- 不买入、不做空、不借贷、不加杠杆；
- 不转账、不提币、不管理地址；
- 卖出后不得低于基础资产保留量；
- 达到额度、库存耗尽或风险暂停后自动停止。

### 2.3 `BUY_SELL`

后置模式，用于完整跨市场套利。该模式必须使用独立权限、独立限额、独立策略版本和更高等级授权，不得通过修改 `SELL_ONLY` 参数启用。

## 3. Binance 权限边界

Binance 现货 API 的交易权限通常允许提交交易相关请求，但 API Key 不是一个可靠的“只能卖不能买”安全边界。项目必须采用纵深防御：

1. 使用独立账户或子账户，只放置可卖资产；
2. API Key 只启用读取和现货交易，关闭提币和内部转账；
3. 使用 IP 白名单；
4. 由 Secret Provider 注入密钥，密钥不进入前端、代码、镜像和日志；
5. 应用层、策略 SDK、执行端和 Fake Exchange 都拒绝 BUY；
6. 对交易请求做交易所、交易对、方向、数量和金额白名单校验；
7. 真实账户只放置可以承受自动卖出风险的低余额库存。

如果必须保证“密钥被盗后也不能买入”，仅依靠 Binance 现货 API Key 无法给出绝对保证，必须使用账户隔离和外部密钥治理降低影响范围。

## 4. 限额配置

### 4.1 硬默认值

以下默认值代表“未启用”，不是可交易额度：

| 配置 | 默认值 | 规则 |
|---|---:|---|
| `enabled` | `false` | 不允许真实订单 |
| `mode` | `DISABLED` | 必须显式切换到 `SELL_ONLY` |
| `venue_allowlist` | 空 | 没有交易所白名单 |
| `instrument_allowlist` | 空 | 没有交易对或资产白名单 |
| `max_order_notional_quote` | `0` | 单笔额度未配置 |
| `max_daily_sell_notional_quote` | `0` | 单日额度未配置 |
| `max_daily_sell_ratio` | `0` | 单日比例未配置 |
| `min_base_reserve` | 未配置 | 不得推断为零 |
| `allow_market_order` | `false` | 禁止市价单 |
| `allow_withdrawal` | `false` | 永久禁止提币 |
| `allow_transfer` | `false` | 永久禁止转账 |

任何一个必要范围或额度没有配置，系统保持安全暂停。

### 4.2 初始候选配置

下面是进入小额候选前的工程安全起点，不会自动写入真实账户：

| 限额 | 候选起点 |
|---|---:|
| 单笔卖出比例 | 不超过该资产可用余额的 10%，同时受绝对 USDT 金额限制 |
| 单日卖出比例 | 不超过该资产可用余额的 10% |
| 基础资产保留量 | 至少保留配置的 20%，除非使用独立的全部退出授权 |
| 单交易对未完成订单 | 1 |
| 下单频率 | 每分钟 1 笔 |
| 最大允许滑点 | 20 bps，按实际市场重新校准 |
| 行情最大年龄 | 2 秒，按部署网络和盘口深度实测调整 |
| 连续拒单 | 3 次后暂停 |
| 未知订单 | 0；出现 1 个即暂停新增订单 |

绝对金额不能由系统猜测，必须由用户明确设置。有效卖出量取以下条件的最小值：

~~~text
min(
  单笔绝对金额换算数量,
  单笔比例换算数量,
  单日剩余额度换算数量,
  单日比例剩余数量,
  可用余额 - 最低保留量,
  交易所允许的最大数量
)
~~~

系统不得通过拆成多笔订单绕过单笔或单日额度。

## 5. 卖出策略边界

策略只产生 `SellIntent`，不得直接访问交易所 API。初期可支持：

- 目标价格或目标净价卖出；
- 分批卖出和时间窗口卖出；
- 移动止盈或受控止损卖出；
- 风险事件触发的减仓卖出；
- 多交易所中可成交净买价较优市场的库存卖出。

每个 SellIntent 必须包含：

- 账户、交易所、交易对和资产；
- 卖出方向和数量上限；
- 策略 ID、策略版本和参数版本；
- 触发价格、参考价格和允许滑点；
- 限额版本和授权 ID；
- 幂等请求 ID；
- 生成时间和行情新鲜度。

策略不能因为库存已经卖完而自动买入补充库存。SELL_ONLY 是自动退出或库存转换能力，不是持续套利能力。

## 6. 订单前置检查

真实订单必须通过全部检查：

1. 当前账户和策略处于 `SELL_ONLY`；
2. 授权有效且未过期；
3. 交易所和交易对在白名单；
4. 方向严格为 SELL；
5. 可用余额和最低保留量满足；
6. 行情没有过期、断线或序列缺口；
7. 最优买盘深度足够；
8. 参考价格、预计成交价和滑点符合策略；
9. Binance `PRICE_FILTER`、`LOT_SIZE`、`MIN_NOTIONAL` 或 `NOTIONAL`、`MAX_NUM_ORDERS` 等过滤器通过；
10. 单笔、单日、比例、频率和未完成订单限制通过；
11. 不存在未知订单、未对账订单或硬风险暂停；
12. 生成并持久化 `clientOrderId` 后才可签名提交。

## 7. 订单状态和重试

~~~text
SellIntent
→ Precheck
→ SignedSubmit
→ Accepted / Rejected / Unknown
→ PartialFilled / Filled / Canceled / Expired
→ QueryAndReconcile
→ LedgerProjection
~~~

- HTTP 5xx、超时和连接断开必须标记 `Unknown`，不能直接重发新订单；
- 必须使用客户端订单 ID、订单查询和用户数据流确认结果；
- 部分成交只允许处理剩余数量，且必须重新经过额度检查；
- 429 进入退避，持续限频或 418 进入连接器暂停；
- 盘口快照和增量无法重建时禁止新订单；
- 取消订单也必须记录请求、响应和最终状态；
- 任何重复请求都必须可通过幂等键识别。

## 8. 自动暂停条件

以下情况触发安全暂停：

- API Key 权限或签名异常；
- 余额与本地账本不一致；
- 出现未知订单；
- 行情超过最大年龄；
- 订单簿序列断裂；
- 连续拒单达到阈值；
- 超过滑点、价格保护或日限额；
- API 429、418、连续 5xx 或多次超时；
- 交易所维护或账户状态异常；
- 数据库、账本或 Secret Provider 不可用；
- GACE stop、升级、网络断开或 Worker 生命周期不确定。

软故障可以在有限次数内重试；硬故障不得自动恢复。恢复必须重新读取真实余额和订单，完成对账，并取得一次新的用户授权。

## 9. 日志、审计和监控

每次自动卖出必须记录：

- 授权 ID、用户主体和限额版本；
- Venue、账户、交易对和策略版本；
- SellIntent、订单请求摘要和客户端订单 ID；
- 参考盘口、价格、数量、费用和滑点；
- 交易所响应分类和最终订单状态；
- 余额变化、账本条目和对账结果；
- 风控检查结果和拒绝原因。

严禁记录 API Secret、完整签名、Cookie、访问令牌和完整敏感请求。

## 10. 验收矩阵

| 场景 | 必须结果 |
|---|---|
| SELL_ONLY 收到 BUY 意图 | 拒绝并审计，不发交易所请求 |
| 未配置额度 | 不发真实订单 |
| 超过单笔或单日额度 | 拒绝，不拆单绕过 |
| 低于最低保留量 | 拒绝 |
| 行情过期或断线 | 禁止新增订单 |
| 订单超时或 5xx | 标记 Unknown，查询后再决定 |
| 部分成交 | 只处理剩余量并重新检查 |
| 重复任务 | 不重复卖出 |
| API 429/418 | 退避或暂停 |
| 余额对账异常 | 暂停并告警 |
| GACE stop 或升级 | 安全暂停，不自动平仓或追加卖单 |
| 日志检查 | 无 Secret、签名和完整敏感请求 |

只有 Fake Exchange、回放、Testnet、只读账户和低余额候选账户全部通过后，才允许评估真实 SELL_ONLY。任何扩大额度或切换 BUY_SELL 的动作都必须重新走授权和验收流程。
